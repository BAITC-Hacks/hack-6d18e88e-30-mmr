# Аудит backend AI Sana — 23 сентября 2026

Проверена рабочая версия ветки `feature/platform-core`: весь `backend/`, общая политика AI, граница между API и TypeScript-клиентом и Python-зависимости. Исправления внесены локально. Проверка не является сертификацией отсутствия уязвимостей.

Повторный аудит аккаунтов, почты и Supabase с новыми исправлениями и актуальными результатами проверок: [docs/audit-backend.md](../docs/audit-backend.md). Разделы ниже сохраняют результаты предыдущих этапов аудита и интеграции.

Работу выполнили основной агент и три независимых агента: HTTP/настройки, AI-провайдер и зависимости. Применены скиллы Codex `conducting-api-security-testing`, `defending-llms-with-guardrails`, `detecting-ai-model-prompt-injection-attacks`, `analyzing-sbom-for-supply-chain-vulnerabilities` и Gemini `master-dev`. Использовались локальные регрессии, MockTransport, анализ исходников, чистая установка зависимостей и реальный loopback smoke. Нагрузочные тесты, чужие системы и реальные AI-ключи не использовались.

## Область и поверхность API

| Маршрут | Назначение | Production-доступ |
| --- | --- | --- |
| `GET /health` | Статус процесса без конфигурации и ключей | Без токена, с проверкой Host/Origin |
| `POST /api/ai/analyze` | Анализ черновика, возможен платный AI-вызов | Bearer + лимиты + строгий JSON + проверка тематики |
| `POST /api/ai/generate-card` | Локальная сборка карточки | Bearer + лимиты + строгий JSON + проверка тематики |
| `GET /api/ai/inspector` | Публичные по замыслу демо промпты и схемы, без секретов | Bearer |
| `/docs`, `/redoc`, `/openapi.json` | Документация | Отключены в production |

Задачи, команды и отклики находятся в браузерном store. Аккаунты, сессии и почта хранятся на backend в SQLite либо используют Supabase. Права собственных профилей и административных рассылок проверяются отдельно; серверного CRUD и объектной авторизации задач пока нет. Серверный API-токен защищает общий доступ к API и сам по себе не является пользовательской ролью.

## Найденные проблемы и исправления

Уровни ниже — оценка практического риска для данного приложения, без формального CVSS. Риск открытого платного API возникает при публичной доступности сервера и настроенном ключе провайдера.

| ID | Уровень | Подтверждение/условие | Исправление и регрессия |
| --- | --- | --- | --- |
| API-01 | Высокий | В исходной конфигурации `/api` не требовал авторизации, включая платный анализ | Development только loopback; production требует серверный токен и явные hosts/origins. `test_api_security.py` проверяет каждый API-маршрут и fail-closed startup |
| API-02 | Высокий | Во время внедрения защиты обнаружен обход через `root_path`: prefixed Inspector давал 200 без токена | Middleware и Router используют один `get_route_path`; отдельные тесты префикса для auth, docs, rate limit и JSON |
| API-03 | Высокий при публичной доступности | Не было ограничений числа запросов и параллельных обращений к провайдеру | 60 изменяющих запросов/client и 300/process за минуту, bounded map, `429/Retry-After`, четыре одновременных AI-вызова; тесты с управляемым временем без нагрузки |
| API-04 | Средний | До схемы тело запроса могло читаться целиком без лимита; лимиты полей не ограничивали JSON-парсер | 256 KiB, 5 секунд чтения, depth 32, 10 000 JSON-узлов, проверка chunked-body без доверия Content-Length. `test_request_validation.py` |
| API-05 | Средний | Повторный `draft` принимался с последним значением; provider envelope принимал повторные ключи и нечисловые float | Строгий JSON на входе и в обоих слоях ответа AI: повторные ключи, NaN/Infinity/overflow, неверный UTF-8 и суррогаты отклоняются |
| API-06 | Средний | Ответ провайдера читался без byte cap, генерация не имела заданного max_tokens | Streaming 128 KiB, model JSON 64 KiB/depth 32, 2048 токенов, общий deadline 3 секунды; таймаут и отмена освобождают слот. `test_ai_provider_security.py` |
| API-07 | Низкий–средний | Ошибка Pydantic отражала присланные значения, включая неожиданные поля | Фиксированный безопасный 422 без исходного input; неожиданный 500 без текста исключения. Проверено на синтетическом маркере; утечка данных другого пользователя не заявляется |
| API-08 | Средний | CORS сам по себе не ограничивал Host, Origin или доступ к development API из сети | Точный allowlist Host/Origin, проверка фактического loopback peer; credentials только для аккаунтов/почты с проверкой CSRF Origin; proxy headers отключаются командой запуска |
| API-09 | Риск воспроизводимости | Версии runtime зависимостей не были закреплены | Закреплены прямые/транзитивные и отдельные test-зависимости, проверена чистая установка, выполнен актуальный `pip-audit` |

Дополнительно устранены интеграционные регрессии: проверка пробельных строк выполняется после trim; ограничен `questionId` и суммарный объём текста; frontend не превращает HTTP 401/403/413/422/429 в локально созданную карточку. Допустимые бизнес-примеры, исходные факты, кириллица, emoji и ручное подтверждение сохранены.

## AI и исходящие запросы

- Прежде чем создавать сетевой клиент, проверяются тематика, попытки сменить инструкции и формат конфигурации. В вопросах модель выбирает поля; текст, ID и отсутствие свободного reason задаются проверенными шаблонами.
- Адреса провайдеров фиксированы HTTPS-адресами OpenAI/NVIDIA. Пользовательский URL не используется; redirect не выполняется, `trust_env=False` не позволяет менять транспорт через proxy-переменные. TLS-проверка не отключена.
- Сжатые ответы провайдера отклоняются до распаковки. Поддельный Content-Length не отменяет фактический byte cap.
- В журнал не попадают тела запросов, ключи и сообщения ошибок провайдера. Логируются только безопасная категория события/имя класса исключения.
- После интеграции аккаунты и очередь почты используют SQLite с параметризованными запросами. Shell/subprocess-выполнение пользовательских данных и `eval/exec/pickle` не применяются. URL в тексте черновика не открываются.

## Проверки и зависимости

Полная воспроизводимая команда: `npm run check`. Она проверяет backend, запускает временный реальный Uvicorn на loopback, проверяет SQL-миграции в PGlite, затем выполняет frontend-регрессии, lint и build. Тестовое окружение отключает dotenv и наследование реальных AI/Supabase/SMTP-ключей; базы и почтовые каталоги временные, отдельные тесты провайдера используют подменённый транспорт.

После интеграции проверены backend, шесть регрессионных frontend-наборов, 38 AI/domain/React DOM-тестов и 45 Vitest-тестов аккаунта/навигации. Loopback smoke проверяет запуск, авторизацию, CORS, offline-карточку, тематический отказ и повторные JSON-ключи. Аккаунты дополнительно проверены на регистрация → подтверждение email → вход → профиль → выход, CSRF, reset/revoke, рассылки по согласию, Strict JSON для PATCH и cookie path под `/gateway`. Python выдаёт deprecation-предупреждение адаптера HTTPX в Starlette TestClient.

Supabase проверен на подменённом транспорте: Auth-сервер проверяет пользовательский Bearer, роль читается из защищённого профиля, ошибки не включают upstream-данные. Ответы ограничены 256 KiB, проверяются JSON и используемые поля; перенаправления, сжатие и proxy-переменные запрещены. Серверный токен и пользовательский Bearer могут передаваться вместе; GET аккаунтов и почты входит в общий бюджет. Локальный PGlite проверяет повторный запуск обеих миграций, сохранение существующих профилей, RLS, запрет смены роли, закрытые почтовые RPC, согласие, отписку и очередь. Это не проверка реальных GoTrue/PostgREST/SMTP, многопроцессной доставки или облачной конфигурации. Облачные миграции при интеграции не запускались.

`npm audit` после объединения frontend-зависимостей: 0 известных уязвимостей на дату проверки. Проверка шаблонов ключей в отслеживаемых файлах обнаружила только явно обозначенный placeholder документации; полноценный аудит секретов всей Git-истории не выполнялся.

`pip-audit 2.10.1` через PyPI: **38 пар пакет/версия, 0 известных уязвимостей, 0 пропусков**, включая новые зависимости Argon2 и EmailStr. Это результат на дату проверки, а не гарантия против неизвестных уязвимостей. Полный машинный отчёт, версии и первичные advisory-ссылки: [security-audit-dependencies.json](../tests/security-audit-dependencies.json). Дополнительная чистая установка Windows/CPython 3.14.4 прошла `pip check` и smoke Argon2/EmailStr; полный интеграционный прогон выполнялся в рабочем окружении.

Linux/macOS и Python 3.10–3.14 проверены по metadata зависимостей, без исполнения на каждой платформе. Lock фиксирует версии, но не хеши wheel/sdist. ОС, Python/pip, frontend-пакеты, содержимое секретных файлов и история Git в dependency-аудит не входили. Значения `.env` не выводились.

## Обязательные условия публичного размещения

1. `APP_ENV=production`, случайный `API_ACCESS_TOKEN` 32–256 символов и точные `API_ALLOWED_HOSTS`/HTTPS `API_ALLOWED_ORIGINS`. Без них запуск завершится ошибкой.
2. Backend-токен хранится только на сервере/gateway. Gateway должен проверять пользователя до добавления токена. Для Supabase он сохраняет пользовательский Bearer и заменяет входящий `X-API-Access-Token` серверным секретом. Неверные и повторные значения отдельного заголовка отклоняются без перехода на Bearer. Открытый proxy с автоматическим добавлением токена всем посетителям не обеспечивает авторизацию.
3. HTTPS, ограничения соединений/тела/таймаутов на внешнем proxy и закрытый прямой доступ к backend. Пример команды с `--no-proxy-headers` приведён в README. Если нужны forwarded headers, список доверенных proxy настраивается отдельно на ASGI-сервере.
4. Лимиты и semaphore в приложении работают на процесс. Для нескольких workers/реплик нужен общий gateway budget; дополнительно задаются расходы/квоты у провайдера.
5. Аккаунты, локальные cookie-сессии, сессии Supabase и права администратора рассылок реализованы. Задачи и отклики остаются в браузере; их серверный CRUD, привязка рабочего пространства к аккаунтам и защищённый gateway ещё не реализованы. Демонстрационный переключатель ролей не является серверной авторизацией.

Регулярные выражения AI-фильтра не являются универсальным семантическим классификатором. Возможны пропуски новых формулировок и ложные срабатывания, поэтому проверки входа дополнены проверками выхода и ручным подтверждением. Реальные провайдеры, публичный deployment и инфраструктура в этом аудите не тестировались.
