# AI Sana — TaskRank & TeamMatch

Frontend MVP: React 19, TypeScript, Vite, Zustand persist и Zod. Русский интерфейс для бизнеса и студенческих команд. Область изменений — `frontend/`, ветка `alim`.

Решения по объединению frontend, core и аккаунтов: [INTEGRATION_NOTES.md](../INTEGRATION_NOTES.md). Ниже описаны возможности, правила расчётов и демонстрационный сценарий.

## Запуск

Нужен Node.js 24, включая встроенный test runner и `registerHooks` для тестового loader.

```sh
cd frontend
npm ci
npm run dev
```

Откройте адрес Vite (`http://localhost:5173`). По умолчанию AI-клиент обращается к `/api/ai/analyze`, Vite перенаправляет запрос на `http://127.0.0.1:8000`. Другой URL задаётся через `VITE_API_BASE_URL` в `frontend/.env.local` (образец `.env.example`); после изменения перезапустите dev server. Ключи AI-провайдера в frontend не нужны.

Backend из `feature/platform-core` поддерживает реальный AI и локальный алгоритм. При отсутствии сервера, тайм-ауте или некорректном JSON приложение показывает локальный режим. Намеренный отказ сервера (HTTP 4xx, OFF_TOPIC, PROMPT_INJECTION) отображается как ошибка и не обходится локальным fallback. Для принудительного локального режима задайте `VITE_AI_MODE=local`.

## Реализовано

- Две роли, раздельная навигация, адаптивные экраны и общие компоненты.
- Конструктор: черновик → уточнение → карточка → рейтинг → публикация. Автосохранение, десять редактируемых полей, теги и источники значений.
- Живая предварительная оценка по семи категориям; рейтинг начисляется только за подтверждённые поля. Четыре уровня готовности и рекомендации по улучшению.
- Явное подтверждение бизнесом перед публикацией; правка карточки снимает подтверждение и публикацию.
- Опубликованная карточка открывается через «Мои задачи» → «Редактировать карточку»; после правки требуется повторное подтверждение и публикация.
- Замена черновика удаляет устаревшие извлечённые поля и вопросы, сохраняя ручные правки и ответы бизнеса.
- Каталог с поиском, фильтрами, сортировкой и полными карточками. Опубликованные задачи низкой готовности принимают отклики.
- Пять команд, отдельные рекомендации с объяснением совпадений, профиль и личные отклики.
- Форма предложения с проверкой полей и HTTP(S)-ссылок, защитой от дубликатов и смены команды во время ввода.
- Обзор бизнеса, рассмотрение и сравнение предложений, независимый ручной выбор нескольких команд.
- Четыре этапа на пару задача/команда с однократным начислением баллов после подтверждения.
- Восемь шагов Demo Mode, сброс с подтверждением, журнал событий.
- AI Inspector: клиентский prompt-контракт, вход, JSON Schema, исходный и используемый ответ, проверка, источник и причина fallback.
- Версионированное сохранение в localStorage, валидация и восстановление повреждённых данных.

Начальные данные: **5 черновиков, 5 опубликованных задач, 5 команд, 6 откликов**. Каталог содержит все четыре уровня готовности.

Все шесть исходных откликов содержат ссылки на собственные учебные материалы `public/demo-prototypes.html`. Это синтетические примеры подхода и прототипа, явно помеченные на странице. После обновления уже сохранённые пользовательские данные не заменяются: новый набор доступен в чистом браузерном профиле или через Demo Mode → Сброс с подтверждением.

## Полный демо-сценарий

1. **1 Черновик** — откроется пример задачи о прогнозировании спроса.
2. **2 AI** — запустится запрос; после ответа или fallback появятся уточняющие вопросы.
3. **3 Рейтинг** → **Заполнить примерные ответы**. Синтетические ответы отмечены явно, предварительная оценка увеличивается; подтверждённый рейтинг пока 0.
4. **Продолжить к карточке** — проверьте десять полей, их источники и оценку. Измените поле для демонстрации пересчёта.
5. **Проверить готовность** → отметьте согласие → **Подтвердить карточку**. Покажите начисленный рейтинг → **Перейти к публикации** → **Опубликовать задачу**.
6. **4 Каталог** показывает задачи; **5 Студент** открывает рекомендации. Общий каталог всегда доступен через навигацию.
7. **6 Отклик** → **Заполнить пример** → **Отправить предложение**.
8. **7 Выбор** — выберите команду вручную. Сравнение нескольких предложений можно показать на исходной задаче Retail.
9. **8 Этапы** — подтвердите Kickoff, затем Prototype. В профиле команды появятся начисленные баллы.
10. Перезагрузите страницу: данные и прогресс сохранятся. **Сброс** → **Отмена** сохраняет состояние; **Сбросить данные** возвращает начальный набор.

Демонстрацию можно начать с середины — используются опубликованные примеры. Публикация, отправка, выбор и подтверждение этапа остаются явными действиями пользователя.

План показа до пяти минут (целевое время, требуется репетиция в настоящем браузере):

| Время | Действие |
|---|---|
| 0:00–0:40 | Открыть черновик и показать слабое описание |
| 0:40–1:30 | Запустить анализ, показать минимум три вопроса и источник ответа |
| 1:30–2:30 | Заполнить примерные ответы, изменить одно поле, показать рост предварительной оценки |
| 2:30–3:00 | Подтвердить сведения, показать начисленный рейтинг и опубликовать |
| 3:00–3:50 | Переключиться на студента и отправить предложение |
| 3:50–4:40 | Вернуться к бизнесу, вручную выбрать команду и подтвердить этап |
| 4:40–5:00 | Показать баллы команды и объяснить повторное редактирование карточки |

## Правила расчётов

| Категория | Максимум | Состав |
|---|---:|---|
| Контекст и потребность | 20 | По 10 за описание процесса и проблемы |
| Данные | 20 | Описание 10, формат 5, объём/доступ 5 |
| Результат | 15 | Описание 10, конкретный вид результата 5 |
| Критерии успеха | 15 | Описание 5, числовая цель 5, метрика 5 |
| Ограничения | 10 | Описание 5, практические условия 5 |
| Пользователи | 10 | Описание аудитории и сценария |
| Коммуникация | 10 | Контакт 5, формат консультаций 5 |

Уровни: 0–39 — черновик; 40–69 — рабочая; 70–89 — готовая; 90–100 — приоритетная. Это эвристика полноты, которая не подтверждает достоверность бизнес-фактов.

`calculateRatingPreview` пересчитывает предварительную оценку во время ввода. `calculateRating` начисляет баллы только при `confirmed=true` за заполненные поля из `confirmedFields`. Сохранённый `Task.rating` и сортировка каталога используют подтверждённый рейтинг. Изменение карточки снимает подтверждение и начисленные баллы до повторного согласия бизнеса; восстановление из localStorage применяет то же правило.

Match = технологии × 35% + навыки × 30% + интересы × 20% + отрасль × 15%. Подбор не назначает исполнителя.

Баллы: Kickoff +5, Prototype +10, Validation +15, Final result +20 — всего 50 за проект. Store проверяет выбранную команду, роль бизнеса и однократность начисления. Бизнес подтверждает фактически выполненный этап; обязательная последовательность программно не навязывается.

## Проверки

```sh
npm run build
npm run lint
npm test
```

Domain-тесты проверяют рейтинг, match, роли, подтверждение, публикацию, отклики, выбор нескольких команд, этапы и localStorage. AI-тесты покрывают корректный ответ, заглушку, неверный JSON/схему, HTTP 503, сеть, тайм-аут и отмену. React DOM-тесты работают с настоящими компонентами App в StrictMode.

Тестовый loader компилирует TS/TSX через TypeScript и заменяет CSS пустым модулем; в production он не используется.

`npm test` запускает frontend unit/DOM-тесты и core regression suites; `npm run check` из корня также запускает backend и изолированный HTTP smoke. Регрессии отдельно проверяют замену черновика, очистку устаревших фактов, начисление после подтверждения, сохранение этого правила после перезагрузки и цикл редактирования опубликованной карточки с изменением позиции в каталоге.

**Ограничение проверки:** браузерная интеграция в текущем сеансе недоступна. DOM-тесты не проверяют визуальный результат, геометрию адаптивной вёрстки и native dialog в конкретном браузере. Перед показом нужно визуально пройти сценарий на desktop и узком экране.

## Структура и границы MVP

`app/` — Zustand и константы; `components/` — общие элементы; `data/` — демонстрационные данные; `features/` — пользовательские сценарии; `services/` — AI, рейтинг, match, сохранение; `styles/` — токены и стили; `types/` — типы; `tests/` — автоматические проверки.

Данные задач находятся в текущем браузере (`ai-sana-demo`, версия 1), не в общей серверной базе. Роли frontend демонстрационные. После интеграции `origin/dev` backend содержит отдельные аккаунты, SQLite и страницу `/account`; переключатель ролей пока не привязан к аккаунтам. Общий многопользовательский каталог требует backend CRUD и серверной проверки правил. Фактический prompt внешнего провайдера принадлежит backend; Inspector обозначает показанный текст как клиентский контракт.
